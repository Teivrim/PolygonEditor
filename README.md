# PolygonEditor

3D-редактор сцен на C++17 / OpenGL. Импорт FBX через Assimp, два
ренддер-бэкенда, CMake, сборка **без сети**.

## Задача

Сделать редактор, который можно открыть на чистой машине и собрать одной
командой. Обычно 3D-тулзы на C++ собираются так: сначала поставь
vcpkg, потом подбери версии библиотек, потом узнай, что у тебя
32-битный Assimp из 2019 года. Здесь зависимости вендорёны, поэтому
`cmake -B build && cmake --build build` работает у всех одинаково.

## Как устроено

```
src/
  main.cpp                 точка входа, lifecycle приложения
  Core/Render/             рендер сцены (GLFW + OpenGL)
  Core/Render/Win32/       рендер интерфейса (Win32 + GDI+)
  Interface/Panels.cpp     панели редактора
  ...
include/
  assimp/  glm/  mpi/      вендорённые заголовки
lib/                      import-библиотеки MinGW и Assimp.dll
```

**Два рендер-бэкенда — осознанное решение.** Сцена идёт через
GLFW/OpenGL, интерфейс — через Win32/GDI+. Можно было тянуть ImGui, но
тогда проект перестаёт собираться «из коробки» и тянет за собой ещё четыре
зависимости. Win32/GDI+ есть в системе всегда.

**`include/` и `lib/` вендорёны намеренно.** Assimp, GLM, MS-MPI —
всё permissive (BSD-3, MIT, Microsoft BSD-подобная). Полные тексты
лицензий — в `NOTICE.md`, и они лежат рядом с кодом компонентов.

## Сборка

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Проверено: CMake 3.30, Ninja, MinGW-w64 g++ 14.2, Windows 11.
Результат последней сборки — в `BUILD-REPORT.md`.

Сеть не нужна: `_deps` не используется, все зависимости в репозитории.

## Что здесь не сделано

Честно, чтобы не было сюрпризов:

- **Нет собственного формата сцены.** Сцена描述 описывается только в
  импортированных ассетах; сохранение проекта не реализовано.
- **Нет интерактивного выбора объектов и gizmo.** Отсюда прямо растут
  следующие версии — план развития на 15 версий лежит в документации
  проекта.
- Модели в репозиторий не кладутся: политика лицензий FBX не позволяет
  раздавать ассеты, поэтому проверять импорт надо на своих файлах.
